Simulation System

Droplet Representation

The droplet template stores the rest-state mesh topology. Each droplet mesh is generated as a spherical cap using radial rings and angular segments, producing a smooth dome-like shape that approximates a real water droplet. Templates store rest vertices, triangle faces, and boundary loop indices — critical for contact-line physics, volume preservation, and droplet splitting.

Each droplet maintains dynamic per-vertex positions and velocities. updateDerived() computes vertex normals, center of mass, and principal deformation axes. Newly spawned droplets are aligned to arbitrary surface orientations via the droplet factory, which transforms template local coordinates into the surface's tangent space.

Merging & Splitting

Droplets merge when centers satisfy distance < factor × combinedRadius. Total volume is conserved and momentum approximated via volume-weighted averages of centers and velocities. Splitting triggers when volume exceeds a threshold and elongation becomes large — two smaller droplets spawn in opposite directions to mimic capillary breakup.

Physics Operators

Modular operators handle distinct fluid behaviors independently:

External Forces Collision Viscosity Surface Tension Contact Dynamics Volume Preservation

Gravity and user interaction update vertex velocities. The collision operator resolves surface penetration, bouncing, friction, and adhesion. Laplacian-based smoothing simulates viscosity and curvature flow. Contact line dynamics model wetting via advancing and receding contact angles. A final volume correction step rescales interior vertices to maintain stable shape.

SingleDropletSolver Pipeline

The solver advances each droplet through a fixed operator sequence using semi-implicit Euler integration with operator splitting:

1Recompute derived geometry
2Viscosity
3Curvature flow
4Contact angle forces
5External forces
6Integration — X += dt × U
7Collision projection
8Volume correction

Surface Representation

Plane Surface
Provides analytical projection, analytical ray intersection, and exact normals.
t = (origin − ray.origin) .dot(normal) / denom
Heightfield Surface
Bilinear sampling interpolates heights from grid samples. Gradient-based normals from finite differences. Sphere tracing raycast uses iterative signed-distance stepping.
normal = (−dh/dx, 1, −dh/dz) // sphere trace t += abs(dist) × 0.5

GPU Rendering Pipeline

GPU Mesh Buffers

GpuMeshBuffer manages VAOs, VBOs, and EBOs. Positions and normals are updated dynamically every frame via GL_DYNAMIC_DRAW. A GPU cache maintains buffers per droplet ID — allocating resources for new droplets and automatically freeing them on removal.

Refractive Renderer — Three-Pass Architecture

Scene Pass
Renders background geometry to establish scene color and depth. renderSceneColorDepth()
G-Buffer Pass
Stores droplet normals, thickness, and depth for deferred compositing. renderDropletGBuffer()
Composite Pass
Combines scene color, refraction vectors, Fresnel reflections, and specular highlights. compositeDroplets()

Interaction System

The drag interaction system allows direct droplet manipulation via mouse input. DragInteractor connects user input to the force-field system. On each update it detects mouse release events, generates a picking ray from the camera, and raycasts against the simulation surface. On valid intersection the drag force field activates and follows the cursor-projected world position.

dragField_->setActive(true); dragField_->setCenter(hit.position);
